WorkBuddy 对话管家  v1.7.0
=================================

双击「启动 WorkBuddy 对话管家.vbs」即可使用，不需要安装任何东西。
（程序调用 Windows 自带的 PowerShell 和 Edge，没有第三方依赖。除了你在模型管理里主动点
  「测试对话 / 获取列表 / 批量导入」时会去访问你自己填的接口地址之外，程序不联网。）

四个功能：对话备份 / 恢复、找回对话、查看全部与彻底删除、账号切换。国内版和国际版都支持，可以同时使用。


〇、两个版本
----------------
国内版和国际版是两套完全独立的数据，程序全程按版本分开处理，不会混：

              国内版                        国际版
  客户端      WorkBuddy.exe                 WorkBuddyAI.exe
  对话数据    %USERPROFILE%\.workbuddy      %USERPROFILE%\.workbuddy-ai
  登录态      ...\auth\workbuddy-desktop.info   ...\auth\workbuddy-desktop-ai.info
  服务域名    workbuddy.cn                  workbuddy.ai

界面右上角同时显示两个版本各自的登录状态，例如：
  ● 国际版 主力号 运行中     ● 国内版 330****1234
没登录的那个版本显示「未登录」。点哪个版本，下面的对话列表、备份、账号
就切到哪个版本；选择会被记住。

那里显示的是昵称（设过的话），没设昵称就显示打码的账号。

两个版本可以同时登录、同时开着，互不影响。


一、对话备份与恢复
----------------
备份：把当前所选版本的对话数据库（workbuddy.db）、该版本的全部本地对话文件
      （<版本目录>\projects）、以及该版本各账号的侧栏快照，整份复制到本目录的
      backups\ 下，每次一个独立文件夹。备份清单里会记下它属于哪个版本。

恢复：三种方式，按情况选
      1) 完整恢复 —— 把对话库整个回滚到备份那一刻：备份之后新增的对话会从
         列表里消失。程序会先自动给「当前状态」再做一份备份（名字以 pre-restore
         开头），所以恢复错了还能救回来。
      2) 按时间同步（v1.6.7 新增）—— 两边都有的对话逐条比大小和时间，把「备份那份更大且更新」的换成备份的，「本机明显更新」的不动：
         · 备份**更大而且更新** → 用备份的覆盖（它更完整）
         · 两边**大小和时间都一样** → 完全相同，不动
         · 备份**更旧而且更小** → 本机明显更新，不动（不会把你新写的回退掉）
         · **其余情况**（更新但更小、更旧但更大）→ 拿不准，**列出来让你自己定**，不会被改动
         备份里有、本机没有的会补进来；本机有、备份里没有的**不删除**（只增不删）。
         和「完整恢复」一样，动手前强制给当前状态再做一份备份。
         界面上：选它之后会自动做一次只读对比（不写任何文件），当场告诉你「覆盖几个 / 不动几个 / 补进来几个 / 拿不准几个」；
         拿不准的会列成清单，每行给出两边的「大小 · 更新时间」，恢复完成后你可以单独处理那几条。

      3) 仅补齐缺失（跨版本恢复用这个）—— 备份里有、这台机器上没有的才补进来：
         数据库里缺的对话会插进去，磁盘上缺的对话文件也会补回；已有的不覆盖、
         不删除，现有列表不受影响。重复点也不会重复插入。

      v1.3.4 之前，「仅补齐缺失」只补文件、不补数据库，所以跨版本恢复看起来
      什么也没发生（对话文件在，但列表里没有对应的记录）。现在数据库和文件都会补。

备份列表怎么看：
- 「已有备份」这个数字只统计当前所选版本。切到国际版就只数国际版的备份，
  不会把国内版的一起算进来。
- 每条备份的归属账号后面标着版本名。如果这条备份不属于当前版本，版本名会
  变成红色——提醒你点「恢复」走的是跨版本恢复。
- 「对话」那一列是这份备份里**实际有多少个对话**（含已归档、已删除，不含云端），
  也就是点「查看」之后能列出来的行数，两处永远一致（v1.5.1）。
  以前这里数的是清单文件里记的条目，而清单是照着当时侧栏渲染的样子写的，归档和
  已删除的对话都不在里面，所以数字会明显偏小。现在直接数备份里那份数据库；只有
  备份里没有可读数据库时，才退回用清单的数字。

关于「查看」窗口（v1.5.0）：列的是这份备份里那份数据库中的全部对话。以前只列侧栏
渲染过的那些，归档、删除、云端的都看不到；现在一份不少。
  - 两行筛选和第三节「查看全部」一样：账号、状态（含「云端」档，云端同样只在选中
    这一档时显示）
    账号一行默认停在「全部」（v1.5.4）：打开这一页要看的本来就是整份备份，不该
    预先筛成一个账号。每个账号显示的是你自己起的昵称；当前登录的那个和「查看全部」
    一样带一个绿点和「当前 · 」前缀，并排在最前面。做备份时的那个账号不再有
    「备份账号」这个前缀，也不排在前面——它在这一页里就是普通的一员。
    归属列同样和「查看全部」一致：当前登录的账号写「当前账号」，其余显示昵称、灰底。
  - 右边的状态列是只读的：显示备份里的状态，三档灰掉点不动，云端行是只读标记
  - 没有搜索框，也不提供任何修改入口
  - 大小列写「仅记录」，表示这条对话在备份里只留了数据库记录、没有正文文件。
    只有两种情况会这样：云端对话（正文存在服务端，本地只有一行记录），或者做
    这份备份时本地已经没有这条对话的文件了。已删除的对话不算——从 v1.5.5 起
    备份会把它们的正文一起带上，见下面「备份和删除的关系」。
  - 底部两个按钮：「关闭」和「恢复这份备份」
如果这份备份里没有可读的数据库，会退回用清单文件来列，状态一律按「可见」显示，
窗口里会明确提示「状态无法判断」。

备份和删除的关系（v1.5.5 起）：
  客户端的「删除」只是给数据库里那一行打个标记，正文文件仍然留在 projects 目录里。
  以前的备份只收「可见」的对话，于是已删除的对话只有一行记录跟着数据库进去，正文
  没进去——在「查看」窗口里显示成「仅记录」，恢复回来也打不开。最要紧的是「彻底
  删除」之前那份自动备份：它本来就是为这些对话留的退路，却救不回正文。
  现在备份会连已删除对话的正文一起收进 projects 目录，恢复时照样还原。代价是备份
  变大一些（已删除的对话越多越明显），换来的是「删前备份」真的能救回来。
  云端对话仍然只有一行记录：正文在服务端，本地从来没有文件可备。

模型管理（v1.5.6 新增，v1.5.8 增加隐藏，v1.6.1 增加批量导入与图标，v1.6.2 整理图标与卡片，v1.6.3 重排卡片与编辑窗口、新增分组切换，v1.6.4 修测试判定与批量进度，v1.6.5 安全加固，v1.6.6 统一列表地址与新增 model.csv，v1.6.7 标签页右键菜单与按时间同步恢复，v1.6.8 标签页视觉与按钮位置，v1.6.9 修 5 个缺陷，v1.7.0 测试结果移到接口行）：
  左边栏第三节，管的是客户端里那些你自己导入的模型。它们存在一个单独的文件里：
  国内版 %USERPROFILE%\.workbuddy\models.json，国际版 %USERPROFILE%\.workbuddy-ai\models.json。
  这个文件里全都是你导入的模型，没有官方模型，所以每一条都能编辑、都能删除。
  页面顶部会写明现在读的是哪个文件。

  改完不用重启客户端：客户端盯着这个文件，一有变化就重新读取（大约 1 秒后同步），
  正在开的对话下一轮就会用上新设置。

  能改的东西：接口地址、API 密钥、备注、图标、三项能力开关（工具 / 图片输入 / 推理）、
  推理档位与默认档位、上下文长度、以及「接口地址原样使用」这个高级开关。

  编辑窗口（v1.6.0 重新整理，v1.6.1 微调，v1.6.3 重排测试流程）：
  - 模型：这一栏就是 id，是客户端定位一条模型的依据。旁边两个按钮：
    「选择模型」从接口拉到的列表里挑一个替换；「测试对话」当场验证这条能不能用。
    改一条已有记录时这一栏是灰底只读的（id 改了等于换了一个模型）；
    新建时可以直接输入，也可以先填好地址和密钥再点「选择模型」挑一个。
    「选择模型」只看接口地址和密钥，不要求 id 已经有值 —— 它本来就是用来选出 id 的。
  - 接口地址：可以只填到 /v1，客户端会自动补 /chat/completions。
  - API 密钥：明文存在文件里，默认打码，点眼睛看明文。
  - 备注：就是文件里的 name。客户端把它显示成「备注:id」，只影响观感，不影响调用。
  - 图标（v1.6.2 重写）：图标写进条目的「服务商(vendor)」字段——客户端就是按它
    挑选显示哪个图标的（它先看 url 能不能对上服务商，再拿 vendor 去比服务商名）。
    一排 16 个图标点一下就选中；虚线框的那几个客户端不一定显示得出来，鼠标停上去
    会说明原因（地区屏蔽 / 只有模型名带关键字才显示）。没手动选过时按
    「厂商 + 模型名」自动匹配，匹配不到就是「未知」。
    图标是从客户端自己的安装包里取出来的原版图形。
    ⚠️ 写 vendor 会顺带影响两处（都不影响能不能用）：客户端里显示的服务商名，
    以及「模型自身没写档位时」的推理档位默认值（本程序每次都写档位，所以这条不显现）。
  - 模型 / 接口地址 / API 密钥这三栏是必填。任一为空时那一栏会标红、保存按钮置灰；
    不填满就存不进去。（标红只在你碰过表单之后才出现，避免一打开就满屏红。）
  - 推理档位（v1.6.3 重修）：只有打开「支持推理」后才出现，五个按钮 低 / 中 / 高 / 超高 / 极致，
    可多选（和客户端自己表单里的档位一致），选中哪几档就原样写进 supportedEfforts。
    下面的「默认档位」是单选下拉，只列出你上面勾中的那几档 —— 没勾的档位选了也没意义。
    （旧版的「关闭（不思考）」已移除：客户端对这个字段的解读和界面预期对不上，
    与其给一个点了不起作用的选项，不如不给；原来的值不会被改写。）
    新建模型时如果开着「支持推理」，「高」和「极致」两档默认是勾上的，多数推理模型都认这两档。
  - 上下文长度：输入上限和输出上限并排一行。单位是 K，1000 = 1K，
    最多三位小数（128.5 就是 128500）。
    注意客户端自己的表单是按 1024 换算的，这里按你说的用 1000。
  - 隐藏模型：在窗口左下角。从客户端列表里去掉，条目仍保留，可随时取消。

  批量导入（v1.6.1 新增，v1.6.3 按模型加图标，v1.6.4 加进度条与地址回填，v1.6.6 统一地址顺序与能力补全）：
  「自定义模型」卡片右上角，最右边那个蓝色的「批量导入」按钮。
    1. 填接口地址和 API 密钥，点「获取列表」。
       地址只填域名也行。候选地址的顺序是固定的四个：
         · 你填的地址原样
         · 域名/models
         · 域名/v1/models
         · 你填的地址 + /models
       依次试过去，谁先给出合法列表就用谁，并把「试过哪些、各自什么结果」都写出来。
       （「选择模型」按钮走的是同一套顺序、同一个函数，两条路不会再互相打架。
         这个弹窗没有「接口地址原样使用」这个开关，所以这里不涉及。）
       **拿到列表后，会把补全好的对话地址写回「接口地址」那一栏**（并提示你换成了什么）——
       否则保存时用的还是你原来那个不完整的地址，模型存进去就不可用。
    2. 拿到清单后默认全选。清单里每一行左侧都会按扫到的模型 id 标上对应图标，
       保存后就按这份写进文件，所以刚才看到什么图标，客户端里就是什么图标。
       清单本身不再限高（v1.6.6）：以前给它设了最大高度，列表内部会多长出一条滚动条，
       和外层弹窗的滚动条叠在一起，看着很像「进度条叠进度条」。现在整份清单自然撑开，
       滚动交给弹窗本身，界面上只有一条滚动条。
       点「测试对话」可以一次性验证整批：**测试时显示进度条**（x / n + 百分比），
       每测完一批就刷新一次，清单里的行会一格格变绿或变红。
       也可以点某一行的「测试」只测那一条。结果显示在该行下方：
       可用是绿字带状态码和耗时，不可用是红字带原因。
       测试失败的会自动取消勾选 —— 它多半在那个端点上用不了，不该顺手写进文件。
    3. 底部填一个备注，点「批量保存」。选中的模型会一次建成完整条目，
       共用同一个接口地址、密钥和备注。

  能力补全：列表 > model.csv > 默认值（v1.6.6 新增）：
  一条模型的能力（支持工具 / 支持图片 / 支持思考 / 推理档位 / 默认档位 / 上下文长度 / 输出长度 / 隐藏 / **图标**）
  按这个顺序取值，谁先有就用谁：
    1. **接口返回的列表里提到了**——以列表为准。不同服务商给的信息差别很大：
       DeepSeek 会给上下文长度、输出上限和推理档位，很多网关一个都不给。
    2. **程序目录下的 model.csv**（和 app.ps1 放一起，随包附了一份模板）。
       首列是模型 id，**可以用 * 当通配符**（例如 glm-* 匹配所有 glm- 开头的模型）。
       * 也可以放在**开头**，这很重要：同一个模型在客户端里有三种 id 写法，
       模板里每家都写了三条，你自己加行时也照这个来——
         裸的        gpt-6-astra              用  gpt-*    匹配
         斜杠前缀    openai/gpt-6-astra       用  */gpt-*  匹配
         点前缀      openai.gpt-6-astra       用  *.gpt-*  匹配
                     global.openai.gpt-5.6-sol
       只写裸的那种，带前缀的 id 一条都匹配不上，会落回程序默认值（连上下文长度都不写）。
       查找顺序：先在所有「不带 * 的行」里找 id 完全相同的；找不到，再按文件里
       从上到下的顺序找第一条通配符命中的行。所以「精确的行」一定优先于「带 * 的行」，
       跟它放在第几行无关。
       但带 * 的行**之间是有先后的**：越具体的写法要越靠前，否则
       deepseek-v4-pro-0813 会被前面某条更宽的 deepseek-* 先截走；
       同理 gpt-oss*（16 万上下文）必须排在 gpt-*（105 万）前面，
       不然开源小模型会被套成旗舰参数。模板里这些顺序都已经排好了。
       后面的列依次是：支持工具 / 支持图片 / 支持思考 / 推理档位 / 默认档位 / 上下文长度 / 输出长度 / 隐藏模型 / 图标。
       其中「上下文长度」填输入上限（maxInputTokens），「输出长度」填输出上限（maxOutputTokens），
       两列各管各的、互不相关，哪列留空就不写哪个字段（客户端跟随自身默认）。
       表头中英文都认（「支持工具」和 supportsToolCall 等价），布尔值认 是/否、支持/不支持、
       开/关、1/0、true/false；档位认 低/中/高/超高/极致，也认 low/medium/high/xhigh/max，
       多个档位用 | 或 , 分隔；上下文长度和输出长度都可以直接写数字，也可以写 128K。
       模板里已经按客户端内置模型清单、以及客户端「添加自定义模型」里的预设条目，
       **预填好了常见系列**（DeepSeek / GLM / Kimi / MiniMax / 通义千问 / OpenAI o 系列等）
       的能力、档位、上下文长度和输出长度，多数情况下你什么都不用改，遇到没预填的模型再加行即可。
       模板里还有主流的通配符兜底行（glm-* / kimi-* / claude-* …），带日期后缀的 id 也能接住。
    3. **默认值**：支持工具=是，支持图片=否，支持思考=是，推理档位=高+极致，默认档位=高，
       上下文长度不写，隐藏=否。
  几条规则：某个模型勾了「支持思考=否」，它的推理档位一律不写；「默认档位」如果不在
  「推理档位」里，会自动回落成第一个档位（否则客户端会显示一个选不了的默认值）。
  model.csv 不存在、或某一行留空，都算「没说」，继续往下一级回落。
  点「获取列表」之后，界面会告诉你这次有多少个模型是从 model.csv 补的、csv 里读到了几行。
  改完 model.csv 直接生效，不用重启程序。

  每条模型的卡片（v1.6.3 重排）：一行的排布是「显示/隐藏开关 → 图标 → 备注：id」。
    开关就是原来的隐藏按钮：关掉即从客户端列表里去掉，条目仍保留，随时能再打开。
    右边三个按钮 编辑 / 测试 / 删除；测试结果显示在下方「接口」那一行的右端。
    隐藏中的卡片整体压成灰底并标「已隐藏」，一眼能和可用模型区分开。
    卡片上只显示接口地址和上下文长度（v1.6.1 起不再显示密钥和来源）——
    密钥是敏感信息，少露一眼少一分风险；要看或要改，点「编辑」进去就能看到。
  卡片上的「测试」按钮和编辑窗口里的「测试对话」走同一条链路（见下）。
  **测试结果显示在这条模型的「接口」那一行的右端**（绿字可用 / 红字不可用），
  不再另起一行、也不会把卡片撑高；没测过的那一行就只是接口地址，也不会打断你正在看的列表。
  测试对话（v1.6.0 新增，v1.6.3 改为「先看返回码」，v1.6.4 修判定）：
  点「测试对话」发一次最小对话请求（max_tokens=1），判据是**宽松**的：
    返回码 2xx、回包能解析成 JSON、而且里面不是一句明确的错误（{"error": ...}）—— 就算可用。
  之所以这么松，是因为「回话内容是空的」不算失败：推理模型只给 1 个 token 时，
  那一个 token 往往花在「思考」上，正文自然是空的，但这并不代表模型不可用。
  （v1.6.3 曾要求正文非空，结果所有推理模型都被误报成不可用；v1.6.4 已改回宽松判据。）
  真正会判失败的只有三种：连不上、密钥被拒（401/403）、以及服务端回了明确错误。
  返回码不对时，它会自动尝试补全接口地址：
  先试你填的地址 + /chat/completions，再试域名 + /v1/chat/completions，最后才试原样地址。
  只要补全后的地址能连上，就把「接口地址」这一栏就地换成补全好的结果，
  并告诉你换成了什么；全部试完都不行，接口地址会标红，并列出试过哪些地址、各自什么状态。
  （「接口地址原样使用」勾上时不猜地址，只测你填的那个；地址结尾有 / 也不会拼出 //。）
  保存按钮（v1.6.3 收窄触发条件）：新建模型、或者动过「模型 / 接口地址 / API 密钥」
  这三栏中任意一栏时，按钮才会变成「测试对话后保存」——点它会先测一遍，通过就自动保存，
  没通过会问你是「返回修改」还是「仍然保存」。只改备注、图标、能力、档位、上下文长度
  这些不碰连接信息的设置时，按钮一直是「保存」，不会再逼你多测一次。
  隐藏模型（v1.5.8 新增，v1.6.3 改成卡片左边的开关）：
  每张卡片最左边那个开关就是显示/隐藏。关掉的做法是把这条的键名 id 改成 -id（值不变）：
  客户端只加载「有 id 这个键」的条目，键名一改，它就从这个列表里消失；
  而这条的 url、密钥、所有字段都原样留在文件里，开关再打开就恢复成原样。
  想彻底去掉请用「删除」——那是不可逆的，所以删除前会再问一次，
  写入前的旧文件也留在 models-snapshots 里。
  页面上被隐藏的卡片会压成灰底、虚线边框，并标一个「已隐藏」。
  同一个 id 有多条时（比如重复导入过），打开其中一条的开关会自动把其它同名条目隐藏，
  只留这一条生效——客户端按 id 认模型，同名多了会互相打架。
  注：隐藏之所以改键名而不是改 id 的值，是因为客户端判断一条模型能不能用，
  看的是「id 这个键在不在」，而不是它的值长什么样。把值写成 -foo 是没用的：
  那是一个非空字符串，条目照样会被加载，只是名字变成 -foo 而已。

  分组切换 / 多个 models.json（v1.6.3 新增，v1.6.6 改文件名格式）：
  客户端只读 models.json 这一个文件，所以「换一份模型清单」在磁盘上就是改文件名。
  模型页顶部那一排标签页就是这件事：
  - 每一页对应同一目录下的一个分组文件。当前客户端真正在用的那一页：边框是蓝色（**底部不封口**，和下方的模型列表连成一片），并且带着一个「当前」小徽标。其余页是灰色边框围一圈、底色略深的独立卡片。
  - 分组文件名是 models<标题>.json（例如 models日常.json）——标题放在 .json **前面**。
    早先的写法是 models.json<标题>，那等于把扩展名改掉了，文件在资源管理器里不再是 JSON，
    也不会被「只看 *.json」的工具扫到。这一版改过来了（不兼容旧格式，旧文件需手动改名）。
  - 标签页最右边是「+」，点一下直接新建一组（不弹确认框）：现在这一组会被存成
    标签页，客户端改用一个全新的空 models.json。
  - 点别的标签页就切过去：现在这组按自己的标题改名存起来，点中的那组改名成
    models.json。重名会自动加数字顺延（无标题 → 无标题2）。
  - 当前那页标题右边有个铅笔，点一下就地改标题。标题里不能有文件名不允许的字符
    （\ / : * ? " < > |），这些会被自动去掉；标题也做长度限制。
  - 标题不是只靠文件名记住的：它同时藏在文件内部一个隐藏条目里（-id 为 ModelFileName，
    name 就是标题），所以来回改名不会把标题弄丢。这个条目在列表里不显示、也不能编辑。
  什么时候有用：一套「日常用」的模型和一套「测试用」的模型分开存，需要时一键换，
  不用每次删了重加。切换只动文件名，不动文件内容。

  标签页右键菜单（v1.6.7 新增）：
  在标签页上点右键，菜单里的项按「这个标签页是什么状态」给：
  - 改名：改这一组的标题（和铅笔是同一件事）。
  - 测试（只对当前那一组显示）：把这组里**每个模型**各测一遍。
    每条用它自己的接口地址和密钥发一次最小对话请求——所以一个组里混着几家服务商也没问题。
    弹窗里有进度条，逐条显示可用/不可用；密钥是加密存的条目没法在这里测，会标出原因，
    让你去「编辑」窗口里填一次再测。
  - 编辑：把这个 json 文件交给系统上「双击 .json 会打开的那个程序」（通常是编辑器），
    你可以直接改文本。改坏了程序会拒绝写入，不会帮倒忙。
  - 删除（只对非当前组显示）：把这个分组文件整个删掉，不可撤销。
  - 当前那一组的菜单里**没有删除**：它就是客户端在读的 models.json，删了客户端就没模型了。
    想删它请先切到别的组。
  - 读不了的文件（不是合法 JSON / 空的 / 读不了）只有「编辑」和「删除」：
    编辑是去修，删除是清掉；其余操作对坏文件没有意义。

  修复（v1.6.9，一轮静态复核发现的 5 个问题）：
  - 编辑模型时，文件里原有的 canDisableThinking 会被删掉。这个字段表示
    「思考不允许关掉」，掉了以后客户端就允许关掉它了。现已保留。
  - 上下文长度/输出上限过去会写成字符串（"128000"），和批量导入写的数字不一致，
    同一个文件里两种类型混着。现在一律写数字（前后端都加了保护）。
  - 备份/恢复附件目录时会多套一层同名文件夹，导致附件落在客户端找不到的位置
    （实测确认）。现已改为把内容直接拷进目标目录。
  - 「按时间同步」里被判为「不动」和「拿不准」的对话，其附件目录本来也会被合并，
    与界面上「这些不会被改动」的说明不符。现已一并跳过。
  - 如果某条模型的密钥是客户端加密存的，本程序会把加密内容当成密钥发出去
    （换来一个看不懂的 401），而不是提示你去编辑窗口重填一次。现已改为明确提示。
    注：密钥是明文时（默认情况）不受影响。

  安全（v1.6.5 加固）：
  这一版修了几处真问题，都不是「看着不舒服」，是会真出事的：
  - 「删除前备份 / 找回前备份 / 恢复前备份」勾上之后，如果备份本身失败了（磁盘满、
    文件被占用等），程序现在会**停下来并告诉你原因**，不会再继续往下删数据。
    之前只是写一条日志就继续，等于你勾了保险、保险没生效、数据照样没了。
    如果你确实不想备份，把那个勾取消掉即可，取消后照常执行。
  - 打开界面的地址现在必须带启动时生成的那个令牌；不带令牌取不到页面内容。
    同时校验 Host 头，挡掉「用别的域名指向本机」这类手法。因为页面里带着令牌，
    之前任何能连本机端口的程序都能把令牌读走，再拿去调用切换账号、彻底删除这些接口。
  - 删除备份时的路径校验收紧了：之前传一个特殊的名字，有可能把整个备份目录删掉。
  - 换账号时「把对话搬过去」现在只搬本地对话，不再动云端对话的记录。
  - 模型测试/选择列表时的错误提示过去会被下一个候选的 HTTP 码盖掉（例如实际是
    「返回 200 但内容不是 JSON」，最后只报「HTTP 404」），现在会保留真正的形状原因。

  其它修复（v1.6.6）：
  - 图标识别补了两个漏网的：名称是中文「混元」的模型过去认不出来（会写成 Custom，
    图标跟着回落），现在认得；o1 / o3 这种不带后缀的 id 也认得。
  - 上面「图标」和「地址补全」这两套关键词表过去前后端各写一份，容易对不上，现已对齐。


  四个容易踩的地方：

  - 字段留空分两种。接口地址（url）和 API 密钥（apiKey）留空时，本程序会
    保留这个字段但把值留空——文件里看得见它现在是空的，而不是凭空消失。
    其余字段（说明、vendor、推理档位等）留空才是把这个键删掉。
  - 接口地址或 API 密钥为空时，这条模型在客户端里仍然看得见，但用不了：
    该发的请求会落到官方接口上而不是你的接口，然后失败。页面会给这种行
    加一条提醒，标明缺了哪个字段。
  - API 密钥是明文存在文件里的。这一页读到什么就显示什么，默认打码，点右边的眼睛
    才看明文。截图或者分享这一页之前留意一下。
  - id 不能重复。同一条 id 只能有一条生效：多条都可见时，客户端只会用其中一条
    （实测是**最后一条**生效，本条注释里记了实验过程），其余等于白写。
    本程序的做法是：把你选中的那条设为可见，其余同 id 条目一律改成隐藏
    （键名 id -> -id，内容原样保留，随时能再点开关切回来），所以最后一定只剩一条生效，
    不用去猜客户端会挑哪一条。另外：一条模型如果连 id 都没有，客户端加载时会直接
    跳过它（只写一条日志，界面不会有任何提示），等于这条根本不存在。
    页面会把这两种情况都标出来。

  为什么要这么小心：客户端读这个文件时不做容错，用的是严格的 JSON 解析，
  只要有一个字符不合法（多一个逗号、少一个引号），整个文件都不会加载，
  而且界面上不会有任何提示——你会直接看到自定义模型全部消失。所以本程序：

  - 读之前先判断文件是否合法。文件坏掉时拒绝任何修改（越改越乱），
    页面会明确告诉你「这个文件现在读不了，先修好它再改」。
  - 写的时候先写一个临时文件、确认能解析、再整体替换过去，
    所以不会出现写到一半的半截文件。
  - 每次写入前，把旧文件在程序目录的 models-snapshots 子目录留一份（按版本分开，
    各留最近 20 份）。真出问题可以直接翻回去。
  - 只动你改的那几个字段，其余字段原样保留；连键的顺序都不会被打乱。

  客户端怎么判断一条模型能不能用（供参考）：它只丢弃「连 id 都没有」的条目，
  其它字段缺失都不会导致丢弃。所以改别的字段不会让整份文件失效，
  唯一会让整份失效的是 JSON 语法错误。

  这一节和「备份 / 恢复」没有关系：它不会把 models.json 写进备份，
  恢复备份也不会动模型设置。

跨版本恢复（v1.2.0 新增）：
  允许把国内版的备份恢复到国际版，或者反过来。点那条备份的「恢复」会先弹出
  一段明确警告：两个版本的数据库结构、字段含义可能不同，跨版本恢复有可能出现
  兼容性问题，恢复后个别对话可能显示不全或者打不开。
  确认要做的话：
  - 无论选「完整恢复」还是「仅补齐缺失」，程序都会先给当前版本再做一份备份，
    所以随时可以退回去。
  - 恢复完成后，界面会提醒你下一步该做什么。
  - 跨版本恢复过来的对话如果挂在旧账号名下，用下面第二节「找回对话」挂到
    当前账号上就能看见。

同版本恢复：备份总是恢复回它自己的那个版本，不会写错目录。恢复国际版的备份
只会写 .workbuddy-ai，也只会重启国际版客户端，国内版不受影响。

关于跨账号：对话是按账号隔离的。如果备份是 A 账号做的、当前登录的是 B，
恢复后要切回 A 才能看到这些对话。界面里有一个可选的「改写对话归属」，勾上之后
恢复时会把备份里那些对话的 user_id 直接改成当前账号，这样不用切号就能看到。
完整恢复和仅补齐缺失都支持改写；跨版本恢复建议勾上，否则补进来的对话仍然挂在
备份的那个账号名下，列表里看不见。改写用的是 SQLite 的 UPDATE，只改归属，
不动对话内容，也不伪造任何凭据。

  备份里带着没合并的事务日志（workbuddy.db-wal）也能改写：程序会先把数据库和
  日志一起复制到临时目录，让 SQLite 自己把日志合并进去，得到一份干净的库，
  再做 UPDATE，最后整份写回。所以「带未合并事务日志」不再是禁用理由。

关于「打开客户端」：恢复和找回都会先关掉对应版本的客户端。做完之后程序不会自己
把它拉起来，而是问你一句——点「好」才打开，点右上角 × 就只刷新页面、不打开。

客户端装在哪是「这台机器」的属性，程序每次都现查，不记死路径。顺序是：
  1) 有客户端正在运行 → 直接用那个进程的 exe 路径（最准）
  2) Windows 的安装记录（注册表 App Paths / 卸载项里的 InstallLocation、DisplayIcon）
  3) 开始菜单里的快捷方式，解析它指向的 exe
  4) 按环境变量拼出来的常见安装位置（%LOCALAPPDATA%\Programs 等）
  5) 之前找到过并记住的路径 —— 但只在文件确实还在时才用
所以装在 D 盘、非默认目录也能找到；换台机器或改了安装位置，记的旧路径会立刻作废。
找不到时界面会明确提示「找不到客户端程序」，不会静默失败。

关于刷新：恢复或找回完成后，页面会自己刷新一次（顺便把最新状态重新读一遍）。
标题「对话管家」右边也有一个刷新按钮，随时可以手动刷新页面。


二、找回对话
----------------
问题在哪：WorkBuddy 把每个对话记在数据库（workbuddy.db）的 sessions 表里，每行带
          一个 user_id，就是它属于哪个账号。客户端只显示 user_id 等于「当前登录
          账号」的那些行。换了账号之后，对话文件明明还在，但 user_id 还是旧账号，
          所以侧栏里看不见。

怎么做：点「本地对话」卡片右上角那个蓝色的「找回对话」按钮。程序会依次：
        1) 关闭当前版本的客户端
        2) 备份当前状态（完整备份，含对话文件），存在 backups\pre-recover-* 下
           （只在勾了上面那个「找回前备份」时才做；取消勾选就没有这一步）
        3) 用 SQLite 执行 UPDATE，把选中对话的 user_id 改成当前账号
           （选中的是已删除对话时，同时把 deleted_at 清空，也就是取消删除）
        4) 把数据库里待写的日志合并回主文件（checkpoint）
        5) 等你确认后再决定要不要打开客户端

为什么必须这么做：数据库是 WAL 模式。直接改文件字节、或者删掉 workbuddy.db-wal，
        客户端一刷自己的页缓存就会把改动覆盖回去——看起来「改了但没生效」。
        这里用的是 Windows 自带的 SQLite 引擎（winsqlite3.dll），和客户端走同一套
        代码路径，所以改完是真正落盘的（改完 integrity_check 依然 ok）。

选哪些：弹出的窗口按「来源账号」分组，列出所有不属于当前账号的本地对话。
        每条后面标着状态：没有标记的是正常对话，标「已归档」的是归档过的，
        标「已删除」的是删掉的。
        - 正常对话、已归档对话：默认勾选
        -         已删除对话：列出来但默认不勾，要的话自己勾上
        也可以整组勾选，或者用「全选 / 全不选」。

已删除的对话不分账号：不管它原来属于谁（包括当前登录的这个号），只要还是删除状态，
        都会出现在列表里，方便你反悔。勾上之后找回，删除状态会被清掉，对话重新
        出现在侧栏里。

只改归属，不动内容：对话正文一个字都不碰，只把 sessions 表里那一行的 user_id
        换成当前账号。status 和 deleted_at 只在「你勾了已删除对话」时才动：
        - 已归档的对话找回后仍然是归档状态（在客户端的归档区里）
        - 已删除的对话找回后取消删除，回到正常列表

找回前备份（默认开启）：窗口最上面有一个「找回前备份」勾选框。勾着就在动手前做一份
        完整备份——数据库、全部对话文件、账号快照，和平时点「立即备份」得到的一样，
        出问题可以直接恢复回去。不勾就直接改，省一次复制。
        不管勾不勾，改完都会回读数据库逐条核对，没改成的那几条会列出来。

云端对话改不了：transport = cloud 的对话，归属记在服务端，本地改没有意义，
        所以不在候选列表里，界面会单独提示有几个。

重复点没关系：改过的对话已经不是「其他账号的」了，再点一次会提示无事可做。

「已归档 N」（v1.3.4）：本地对话页「当前账号可见」下面会多一行蓝色的「已归档 N」，
        点它会告诉你去客户端哪里看。已归档的对话不在侧栏的普通列表里，
        路径是：WorkBuddy 内 → 点左下角头像 → 设置 → 数据管理 → 归档的任务。


三、查看全部对话与彻底删除
--------------------------
点「本地对话」卡片右上角的「查看全部」，会打开一个窗口，列出数据库里的全部对话，
包括已归档和已删除的——侧栏里看不到的那些也在这里。

窗口上方有两行筛选：
  第一行 账号：默认选中当前登录的账号；「全部」那一项不按账号过滤。
          每个账号后面的数字是它本地的对话数，不含云端（云端是单独一档）。
  第二行 状态：全部（默认）/ 可见 / 归档 / 删除 ┃ 云端。数字随上面选的账号变化。
          「全部」是前面三档的合计。「云端」前面那道竖线（v1.5.0）表示它和前三档
          不是同一个维度：只有点「云端」才看得见云端对话，选可见 / 归档 / 删除 /
          全部都不会把云端混进来。本地对话和云端对话各算各的，互不干扰。
  下面还有一个搜索框，按标题和路径过滤。

每行标题下面那行小字是「对话 ID 前 8 位 · 对话所在目录」（v1.5.4 修正）。之前这
里显示的是 projects 下的目录名，像 c-Users-batvb-WorkBuddy-2026-10-29-22-12-52，
它是把路径里的「:」和「\」压成「-」得到的，不是路径；现在改成显示数据库里记的
真实目录，例如 C:/Users/batvb/WorkBuddy/2026-10-29-22-12-52。目录名太长时会被
截断，鼠标停在上面可以看到完整路径。云端对话本地没有目录，这一行只显示 ID。

列表最右边的「状态 / 设置」列就是开关，三档：
  可见  = 正常对话，出现在侧栏的普通列表里
  归档  = 收进客户端的归档区，不占侧栏
  删除  = 打上删除标记，侧栏和归档区都不显示
点一下立刻生效（不用再去客户端里操作），但客户端开着的时候这一列是灰的、点不动：
客户端一直持着数据库并缓存页面，它在跑的时候改下去会被它覆盖回去，所以必须先关掉
客户端。

云端对话（标「云端」的）没有这个开关，显示的是一个只读标记（v1.5.0）：
  云端 · 只读      正常的云端对话，状态记在服务端
  云端 · 已归档    服务端那边归档了
  云端 · 已删除    服务端那边删掉了，本地只留一条墓碑记录
这三种本地都改不了，也不参与下面的「彻底删除」——清空已删除对话只处理本地对话。
之所以把云端单独拿出来当一档：云端的行带着 deleted_at = -1 这个标记，以前会被
算进「可见」，和本地对话混在一起，本地的数字看着就偏大。

同一套口径也用在主界面上（v1.5.2）：「本地对话」卡片顶上那三个数字——本地对话、
当前账号可见、已归档——都只数本地，下面那个对话列表也只列本地对话。云端对话不会
出现在这里，要看得点「查看全部」再点「云端」。这样三个数字和列表行数始终对得上，
不会出现「本地对话 31、可见 27、列表却有 36 行」这种各说各话的情况。
（云端对话本身是能正常用的，只是它的正文存在服务端，本地这行只是镜像，统计它的
「本地占用」没有意义。你在客户端侧栏里照样能看到、能打开。）

底部原来那个「关闭」按钮换成了红色的「彻底删除」——它不是关窗口（关窗口点右上角的 ×），
而是清空已删除的对话。点开之后：
  - 「删除前备份」默认勾着：动手前先做一份完整备份（和点「立即备份」得到的一样）
  - 下面按账号列出所有处于删除状态的对话，默认全选，也可以整组取消
  - 底部是「取消」和「清空已删除对话」
确认后程序会：关闭客户端 → 做备份（如果勾着）→ 删掉数据库里这些行 → 删掉对应的
对话文件、附件缓存目录和回滚日志 → 清掉各账号侧栏缓存里的对应条目 → 校验数据库。
这一步是真删：数据库记录和文件都没了，只能靠那份备份恢复，所以默认建议让
「删除前备份」保持勾选。

只删「已删除」的：确认时程序会重新读一遍数据库，只处理仍然是删除状态的对话。窗口
开着的时候你把某条改回可见了，它就不会被删。处理完照例会问你要不要打开客户端。


四、账号切换
------------
0. 「保存当前登录」左边有两个按钮：
   - 「打开客户端」：客户端没开就点它启动；已经在跑的时候按钮变成「关闭客户端」，
     点一下会先弹确认（提示正在进行的任务会被中断），确认后才关掉。
     （v1.3.9 起不再叫「重启」，要重启就是先关再点一次打开。）
   - 「登录新账号」：想登一个全新的号时用。弹窗标题是红字「切换到 新账号？」，
     流程和第 3 步一样，只是最后一步变成「清空当前登录态并重新启动客户端」，
     然后你在客户端里登录新号即可。
     当前账号会**先自动存进快照**（这是硬性前置：存不成功就中止，不会把旧 token 弄丢），
     存好之后原来的登录态文件才被清掉——内容已经在「已保存账号」里了，想切回来点一下就行。
1. 在客户端里登录一个号，回到本程序（右上角选中对应版本）点「保存当前登录」
2. 在客户端里换另一个号登录，再点一次「保存当前登录」
3. 之后在账号卡片上点「切换到此账号」，确认弹窗里有两个选择：
   - 「切换并重启」：先存当前登录态 → 关闭该版本客户端 → 覆盖登录态文件 → 重新启动。
   - 「仅切换」：同上，但**只关不开**，登录态换好之后客户端保持关闭，你想什么时候开自己点
     「打开客户端」。适合「先换好再手动开」的场景。

给账号起昵称（v1.2.0 新增）：
- 账号数字右边有「+ 添加昵称」，点一下出现输入框，回车保存（Esc 取消）。
- 存过昵称之后，那里就显示昵称和一支小铅笔，点铅笔可以改；没设昵称才显示
  「+ 添加昵称」。
- 当前登录的账号那边也会同步显示同一个昵称。
- 右上角的版本按钮显示的就是昵称，一眼能分清哪个版本登的是哪个号。
- 昵称只存在本程序里（data\nicknames.json），不会写进客户端，也不会上传。

登录态还剩几天（v1.3.0 新增）：
- 每个已保存账号的卡片右上角直接显示「剩 N 天」，剩 7 天变红、剩 20 天变黄、
  其余绿色；过期显示「已过期」。
- 鼠标停在上面能看到具体到期时刻和上次续期时间。
- 怎么算的：登录态文件里有三个明文时间戳，其中 refreshExpiresAt 是 refresh
  token 的到期时刻，每成功续期一次就重置为「当时 + 30 天」。所以 30 天内在
  客户端里打开过这个号，它就一直是活的；超过 30 天没动过，就必须重新登录。
- 注意「没过期也可能要重新登录」：客户端每次续期都会换一份新 refresh token 并把
  旧的作废，如果快照里存的是已经被换掉的那份，切过去照样要登录。这不是时间到了，
  是 token 被替换了——本程序每 20 秒同步一次快照就是为了堵这个洞。

版本隔离：账号列表只列出「当前所选版本」保存的账号。
  - 国内版只能切到国内版保存的账号
  - 国际版只能切到国际版保存的账号
快照分别存在 profiles\workbuddy-desktop\ 和 profiles\workbuddy-desktop-ai\ 下，
物理上就是分开的，切换时也只动该版本的 .info 和进程。

登录态文件位置：
  %LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop.info     （国内版）
  %LOCALAPPDATA%\CodeBuddyExtension\Data\Public\auth\workbuddy-desktop-ai.info  （国际版）

程序只是把这份文件整份复制进 / 复制出，不解密、不修改内容。

有两个坑要知道：
- 客户端每次自动续期都会换一份新的 refresh token 并把旧的作废，而它只写活动的
  那份文件。所以程序每 20 秒检查一次，两个版本都会检查，发现续期了就把最新
  登录态同步回同一账号的快照（只更新同一个账号，不会覆盖别的账号）。
- 不要在客户端里手动切换账号，那样会直接覆盖登录态文件，被切走的那个号如果没有
  快照，就得重新扫码登录。换号请用本程序。

登录态有效期：refresh token 每成功续期一次就重置为「当时 + 30 天」。
30 天内在客户端里打开过这个账号，它就一直是活的。


五、目录说明
------------
  app.ps1                                  程序主体
  ui.html                                  界面
  启动 WorkBuddy 对话管家.vbs              双击入口（后台启动，不弹黑框）
  profiles\<版本>\<账号ID>.info/.json      账号登录态快照
  backups\<时间戳>\                        对话备份（manifest.json + 数据）
  data\nicknames.json                      账号昵称
  data\db-snapshots\                       恢复/改写前临时暂存的数据库副本
  data\app.ico                             桌面快捷方式用的图标（自动生成）
  data\                                    运行日志、窗口缓存

关于启动方式（v1.3.9 起）：
  以前那个 .cmd 会先弹一个黑色的命令行窗口再消失，看起来像闪一下。
  现在改成 .vbs：它用 wscript 启动，wscript 本身是图形程序、不创建控制台，
  PowerShell 又是以「隐藏窗口」方式拉起来的，所以整个过程一个黑框都不会出现。
  .cmd 已经删掉了——它唯一的用处是出问题时能看到报错，需要的时候自己开个
  PowerShell 窗口，在里面直接执行 app.ps1 就行，报错同样能看到。

  v1.5.0 起，.vbs 启动前会先看同目录下有没有 app.ps1：没有就弹窗提示
  「找不到 app.ps1——你可能是在压缩包里直接双击运行的，请先把整个文件夹解压
  出来再运行」，然后退出。在压缩软件里直接双击是很常见的误操作：压缩包里的
  文件是先解到临时目录再执行的，app.ps1 和 ui.html 都不在那儿，双击了也只会
  一闪而过、什么都看不到。这个提示框用的是 Windows 自带的消息框，中文显示正常。

左下角两个按钮：
  「桌面图标」在桌面创建「WorkBuddy 对话管家」快捷方式，指向「启动 WorkBuddy
              对话管家.vbs」。图标是程序自己画的 WB 圆角方块（和窗口左上角那个
              一样），不是 WorkBuddy 的图标，免得两个图标混在一起分不清。
              图标文件生成在 data\app.ico。
              重复点只会更新已有的快捷方式，不会出现两个。
              建不成的兜底（v1.5.0）：桌面被重定向到 OneDrive、桌面目录只读、
              或者调用系统的快捷方式组件被安全软件拦住时，程序改在「程序自己
              所在的目录」里建一个，弹窗会告诉你建在了哪，把它拖到桌面就行。
              快捷方式写完后程序会回头确认文件确实在，不会「报成功其实没写」。
              弹出的结果窗底部还有一个「打开应用目录」按钮，点开就是程序所在的
              文件夹（app.ps1、ui.html 就在里面），不管图标建成功还是没建成都有——
              被安全软件拦下时，至少能自己去目录里双击 vbs。
  「退出程序」关掉后台进程（不影响 WorkBuddy 客户端）。

桌面图标为什么曾经是马赛克（v1.5.3 已修）：
  一个 .ico 文件里可以并排放好几张同一图案、不同尺寸的图。Windows 不会按需要
  现画，它只会在里面挑一张「最接近的」再拉成它要的尺寸。这里踩了两个坑。
  一，以前只放了一张 256x256。Windows 要 32 的时候里头没有 32 的图，只能把
  那张 256 硬缩下去，缩完的笔画对不齐屏幕像素格，边缘出现一块一块的台阶。
  二，补了小图之后还漏了一点：桌面图标的尺寸是能按住 Ctrl 滚轮调的，可以调出
  81 这种非标准值。那时里面只有 16/24/32/48/64/128/256，离 81 最近的是 64，
  于是 Windows 拿 64 放大 27% 来用——原来 4 个像素被拉成 5 个，笔画上多出一排
  重复的像素，看着还是一格一格的。
  现在一次写 11 张：16 / 20 / 24 / 32 / 40 / 48 / 64 / 80 / 96 / 128 / 256，
  每张都按自己的目标尺寸单独绘制，不是缩放出来的。这样不管 Windows 要哪个
  尺寸，最接近的那张都和它差不了几个像素：81 会落到 80 上（只差 1.2%），96
  正好有 96（以前是拿 64 放大 50%）。80 这一张就是专门为这种非标准尺寸留的。
  其中 16 / 20 / 24 三张画的是一个放大的 W，不是 WB：那个尺寸下两个字母挤在
  一起只会糊成一团，单个字母反而认得出来。
  旧版本留下的 app.ico 张数不对（早期只有 1 张），程序认出来会自己重画，不用
  手动删文件；想强制重画，删掉 data\app.ico 再点一次「桌面图标」即可。
  换完之后桌面可能还显示旧图标，那是 Windows 的图标缓存，按 F5 刷新一下桌面
  （或在任务管理器里重启「Windows 资源管理器」）就正常了。


六、安全
--------
- profiles\ 里是能直接登录你账号的凭据文件，不要分享、不要传网盘。
- 程序只监听 127.0.0.1，每次启动随机生成一个访问令牌；打开界面的地址里就带着它，
  不带令牌既打不开界面、也调不动任何接口。注意这挡的是「误触」和「别的网页碰到」，
  不是一道安全边界：能在这台机器上运行程序的人，本来就能直接读写那些文件。
- 关掉窗口后后台进程会在十几秒内自己退出，不留残留文件；也可以点左下角「退出程序」。


七、后台什么时候退出
--------------------
界面是浏览器窗口，真正的逻辑跑在后台的 powershell 进程里。它这样决定什么时候退出：
  1) 你关掉窗口 → 后台发现窗口没了（约 10~15 秒确认）→ 退出，顺手删掉
     data\instance.json 和 url.txt，不留残留。
  2) 你点左下角「退出程序」→ 立刻退出。
  3) 兜底：连续 100 秒没有任何页面请求才退出。

为什么以前会「几分钟不管再刷新就报错」：浏览器会把不在前台的窗口里的定时器降频，
最慢到一分钟一次。而旧版后台 28 秒收不到心跳就判定「没人用了」，于是自己退出——
等你回到窗口一刷新，服务已经没了。v1.3.4 起这条兜底放宽到 100 秒，并且优先看窗口
本身还在不在，不再靠心跳猜。

重复双击启动（v1.3.6）：程序会先看已经有什么，再决定怎么办。
  - 窗口还开着、后端也活着 → 不再开第二个窗口，直接把已有的那个调到前台，然后自己退出。
  - 只剩后端（窗口关过、进程没退干净）→ 先把旧后端关掉，再正常启动一个新的。
  - 只剩窗口（后端挂了或被杀，页面已经打不开）→ 先把那个死窗口关掉，再正常启动。
  - 什么都没有 → 正常启动。
  关窗口只针对本程序用私有浏览器配置打开的那个（命令行里带 window-profile 的），
  你要是在自己的浏览器里开过页面，那个标签页不会被关掉。
  判断「窗口在不在」是按窗口标题找的，所以别把标题改掉；改了也不影响启动，
  只是会被当成「没有窗口」处理。

注意：界面文件 ui.html 每次请求都重新读取，但 app.ps1 是启动时加载的。
所以更新过程序之后，必须点「退出程序」再重新启动，否则跑的还是旧逻辑
（界面看着是新的，行为却是旧的）。
